## Findings

**r4.1 A chart pin need not be a version (4.1).** The sentence: the chart is consumed "at its pinned version". The code: `upstream.version` is `str()` (chart/chart.schema.yaml:31), passed verbatim to `helm template --version` (scripts/render-chart.sh:19-22) and `helm install --version` (test/install/install.go:86-93); helm reads that flag as a constraint, so `^10` or `>=0.12` resolves to the newest match. The Renovate regex (renovate.json5:298) captures any non-space token. Nothing in validate rejects a range. Separately, a chart repository can republish the same version: no digest or `--verify` is recorded, unlike upstream sources (Req 1.3). Affected: a release's deployed chart could move without a diff. Today every pin is exact (v1.21.3, 10.5.15, 0.12.1). Severity: low.

**r4.2 The compat decision's README half is unchecked (4.5).** The sentence: the decision is recorded as metadata AND documented in the chart's README. The code: lint-compat.sh:43-109 reads chart.yaml and image.yaml only; the schema (chart.schema.yaml:35) takes any string for `issue`. Probe: README deleted and issue "n/a", lint-compat exit 0, yamale success. Affected: the owner's view (a second compat variant could ship with a structured record and no written reasoning). Severity: low.

**r4.3 The non-root policy reads the pod only (4.6).** The sentence: Kyverno policies requiring "non-root execution". The code: policies/require-nonroot.yaml:25-28 matches `spec.securityContext.runAsNonRoot: true` and nothing at container level. Probe (/tmp/r4probe/dep.yaml): container `runAsNonRoot: false, runAsUser: 0, privileged: true` under a pod with runAsNonRoot true: pass 3, fail 0, exit 0. The e2e's RestrictedViolations (test/checks/securitycontext.go:53-58, effective values) would catch it on a live pod, so a release is protected only through the e2e, which runs per affected component on pull requests. Affected: the chart gate is weaker than stated; docs say "workloads non-root" (see r4.9). Severity: medium.

**r4.4 cert-manager's install deviation is not in its README (4.7).** The sentence: every deviation from upstream defaults is documented with its rationale in the README. The code: test/e2e/components_test.go:30-31 adds `--set crds.enabled=true` ("the issuance probe needs them"); chart/cert-manager/README.md:25-31 does not list it, and its recipe (README.md:11-16) and the user manual's (docs/user-manual.md:223-228) leave it out. Affected: a consumer following the README installs cert-manager without its CRDs, which the e2e never tests. Severity: medium (a consumer's install differs silently from the tested one).

**r4.5 A review-by bump alone clears the lapse (4.8).** The sentence: validation fails "until that decision carries a fresh review-by date from a dated re-decision". The code: lint-compat.sh:91-108 checks review_by >= today and >= decided_at; it never requires decided_at to change. Its own message asks for "a new decided_at and review_by" (lint-compat.sh:106) without enforcing it. Probe: review_by 2099-02-24, decided_at 2026-08-25, DHC_TODAY 2026-11-25: exit 0. Affected: the owner's view (a lapse can be cleared without a dated re-decision, and with no upper bound on the new date). Severity: medium.

**r4.6 The daily lapse report has two unreached cases (4.9).** The sentence: the scan pipeline reports each lapsed compat review-by date in its daily run. The code: check-authenticity.sh:53 exits before the compat loop (:150) when the active-set reader refuses; a chart.yaml that fails to parse yields an empty review_by and `continue` (:154-160) without a message. Both states are also refused by validate on any pull request, so they reach main only by a direct push. Affected: the owner's daily view for that day. Severity: low.

Code: test/e2e/components_test.go:31 installs with `--set crds.enabled=true`, outside the overlay. Same affected party as r4.4. Severity: medium (consumer).

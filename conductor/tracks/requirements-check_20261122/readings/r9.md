## Findings

**r9.1 (9.7) The revocation check skips repositories whose definition was deleted.** The criterion says IF a catalogue tag references a recorded digest THEN the daily run reports it. check-revocations.sh only sees the enumeration. enumerate-catalogue.sh:57 builds that from `$ROOT/image/*/image.yaml`, so it reads only repositories with a definition directory. The record carries `image:` (revocations.yaml:24), but check-revocations.sh:37-51 never lists that repository itself. Deleting a definition directory is allowed (CONVENTIONS.md:534-535: "deleting the directory passes"), and it has happened: drill-app's directory left in b90900f (#378). If a tag still pointed at a revoked digest there, the run would stay green. Affected: a consumer pulling such a tag. Severity: medium. Today the drill's version is deleted (ledger :224), so nothing is exposed.

**r9.2 (9.12) A pull request can get no portability block and still go green.** build.yml:737-759 runs under `set -uo pipefail` without `-e` and with `continue-on-error: true`:
1. The authoritative normalisation's exit (:747) is not checked.
2. vex-portability.sh then exits 2 ("no authoritative record", vex-portability.sh:67-69) and writes nothing.
3. `cat .portability/block.md` (:759) fails, so the step fails, but the job stays green.

A failed vex-portability.sh with a written block (gating true) also ends green, because the step's last command is `cat`. Affected: the owner's view of a pull request, which shows no block and no red. Severity: medium.

**r9.3 (9.12) The rescan can drop a supported manifest from the block, and still counts it.** rescan.yml:513: when the authoritative normalisation fails, the manifest is skipped (`continue`), adding only to `unmeasured`, with no warning line. rescan.yml:524 pipes vex-portability.sh into `grep -c ... || true`, so its exit (2 or 1) is lost, and `blocks` still increments (:525) for a manifest whose block section was never written. The step is `continue-on-error: true` (:499). The summary line (rescan.yml:960) can then say "n compared" for blocks that do not exist. Severity: medium. Statements on that digest get no portability result, and nothing says so beyond a count.

**r9.4 (9.13) The smoke test does not run the recipe verbatim, and the published recipe hides two failures from a consumer.** The recipe that render-verification.sh writes sets no `pipefail`:
- The SBOM line pipes `cosign verify-attestation` into `jq` (render-verification.sh:197-198).
- The VEX line pipes the braced pair into `jq > openvex.json` (:205-207).

A failed cosign therefore ends in an exit 0 from jq, with empty output (or an empty openvex.json). consumer-smoke.sh:98 runs each step as `bash -o pipefail -c`, each in its own process, so the smoke test catches what a consumer running the README block would not. The run is also logged in to ghcr.io (rescan.yml:106-111), which a consumer is not. The criterion says "verbatim"; the code adds pipefail and credentials. Affected: a consumer scripting the recipe, who gets exit 0 on a failed SBOM or VEX verification; and the daily proof, which proves a stricter recipe than the one published. Severity: high (a consumer can be wrong silently). lanes.md:1092, :1107-1108 and :1143 record it as an open item.

## Findings

**r7.1, 7.2: yamllint skips three paths (low).**
- **The sentence:** yamllint runs "on changed YAML files".
- **The code:** validate.yml:25 runs `yamllint .`, but .yamllint.yaml's `ignore` drops data/, temp/ and chart/*/templates/. A YAML file added or changed under data/ is never linted. The template exclusion is necessary (Helm templates are not YAML), and chart.yml renders them instead.
- **Who is affected:** nobody today (no YAML file under data/ or temp/). A future research input could merge malformed.

**r7.2, 7.4: codified conventions that no CI step checks (medium).**
- **The sentence:** a pull request violating "a codified convention" fails CI naming it.
- **What CONVENTIONS.md says of itself:** "CI enforces what it can ...; reviewers hold the rest" (:3-4), and "a rule naming none is a convention held at review" (:144-145). Conventions it codifies with no check:
  - alpine only, "A convention, not a lint" (:176-179);
  - the modification notice on a definition copied from the DHI catalog (:184-194);
  - the ldflags version stamp and dotted annotation keys, which "stay with the reviewer" (:297-298);
  - chart deltas only in config/values-hardened.yaml, and every deviation in the chart README (:353-373, Req 4.1, 4.7);
  - one logical change per pull request, the TL;DR, and requirement ids in the body (:516-524);
  - the release tag shape `<semver>-<os><osver>[-<variant>]` with both alias tags (:9-15). lint-pins.sh:101-115 and :242-252 check only OCI validity and that each tag states the declared version.
- **Who is affected:** the owner's view. "Enforced mechanically" is weaker than the sentence; these violations reach review only.

**r7.3, 7.10 (also 7.4): a string permissions block crashes the workflow lint (low).**
- **The code:** lint-workflow-policy.sh:101-110 calls `.get` on the permissions value. GitHub accepts `permissions: write-all` / `read-all` as a string.
- **Probe:** chart.yml's block replaced by `permissions: write-all` in /tmp/r7probe. The lint exits 1 with `AttributeError: 'str' object has no attribute 'get'` and no `::error` line.
- **Effect:** validation still fails, so no silent pass, but "naming that value" (7.10) and "identifying that convention" (7.4) do not hold for this case.

**r7.4, 7.5: govulncheck's checksum is not recorded here (low).**
- **The code:** build.yml:778-792 runs `go install golang.org/x/vuln/cmd/govulncheck@v1.6.0`. The checksum control is the public Go sumdb, not a value in this repository, and the inline comment says so (:778-780).
- **Impact:** the step is non-gating (continue-on-error).

**r7.5, 7.5: the Renovate validator's npm tree floats (medium).**
- **The code:** validate.yml:332-340, `npm install --no-save renovate@41.173.1 json5@2.2.3` with no package-lock.json. The two top-level versions are exact. Every transitive dependency resolves to whatever its semver range allows on the day, and npm checks each tarball only against the registry's own integrity field. Nothing is recorded here.
- **Who is affected:** every validate run. A required check executes several hundred third-party packages that no pin or checksum in this repository names, the CVE-2026-33634 shape CONVENTIONS.md:99-102 warns about. The job holds only `contents: read`, which limits the reach.

**r7.6, 7.5: executables chosen by action defaults or setup actions (medium).**
- **build.yml:193** `docker/setup-qemu-action` with no `image:` input installs the binfmt/QEMU emulators from its default image, `tonistiigi/binfmt:latest` per the action's documented default.
- **build.yml:194** `docker/setup-buildx-action` with no `driver-opts` starts BuildKit from its default `moby/buildkit:buildx-stable-1`. That daemon runs every release build that is then signed.
- **actions/setup-go** (validate.yml:350, e2e.yml:131, rescan.yml:92) downloads a Go toolchain.
- **renovate.yml:46** runs a Renovate container chosen inside the action.

None carries a version or checksum recorded in this repository. The action SHAs are pinned, but the defaults named above are moving tags. The two Docker defaults are read from the actions' documentation, since the action sources are not in this tree; one release run's log would confirm them. Who is affected: a release (a substituted BuildKit image would build what gets signed, with no check here able to notice) and the owner's view of 7.5.

**r7.7, 7.6: an Actions bump runs the definition refresh and fails (medium).**
- **The code:** renovate.json5:416-421 attaches `scripts/refresh-definition.sh {{{packageFileDir}}}` to every update whose datasource is github-tags. Renovate's built-in github-actions manager (enabled at :12) resolves actions through github-tags, which the rule at :465-474 itself states. renovate.yml:57's allowlist `^scripts/refresh-definition\.sh .+$` admits `scripts/refresh-definition.sh .github/workflows`.
- **What follows:** refresh-definition.sh exits 1 with "refresh: no image.yaml in .github/workflows". The grafana precedent at renovate.json5:427-431 shows a failed post-upgrade task aborting the run.
- **No guard:** the fixtures (managers.test.mjs:890-895) check that github-actions is enabled and not automerged, but nothing checks which rules carry a postUpgradeTask.
- **Who is affected:** the owner. The pins "carry a manager" on paper, and bumps likely never arrive. That last part is the earlier pass's live reading, which these files cannot show.

**r7.8, 7.6: a newer major waits for approval (low, deliberate).**
- renovate.json5:336-341 puts every major behind Dependency Dashboard approval (Req 3.4), so the sentence's "SHALL open a pull request" holds only after the owner approves. cosign's v3 line is the live case (install-tool.sh:85-92).
- The conflict is between 7.6 and 3.4 as written. Either 7.6 is worded to except majors, or it stays read as "offered".

**r7.9, 7.7: dispatch inputs without allowed values, drill substitutes not beside the input (low).**
- **The sentence:** each dispatch input is declared "with its allowed values, a drill's substitute values beside it".
- **The code:** build.yml `image` and e2e.yml `component` are `type: string` with no allowed values (catalogue-policy.yaml:254-256, :306-308). Their allowed values (an active definition, a chart directory deploying one) are enforced at run time instead (build.yml:89-94). The drill substitutes live in triage.drills (:197-199), cross-referenced by comment from the input at :269.
- **Effect:** the values are declared and held, so this is wording.

**r7.10, 7.11: the ledger lint checks rows, not the LOG half or the reasons (medium).**
- **No LOG check:** lint-live-evidence.sh has no step that reads triage/LOG.md. "And in triage/LOG.md" has no check.
- **Criteria, not mechanisms:** rows are keyed per criterion (:64-97). A criterion resting on several mechanisms (7.5 on two install scripts, pip and npm) has one row.
- **Any reason passes:** `unexercised` passes with any non-empty text (:88-89), while the sentence admits only mechanisms a live exercise would harm consumers with. Rows 2.26, 3.15 and 4.9 give other reasons, and 2.28 waits on the successor.

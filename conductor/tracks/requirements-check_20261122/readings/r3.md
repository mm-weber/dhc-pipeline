## Findings

**r3.1 (Req 3.2, also 3.1 and 3.14): the definition refresh task fires on every GitHub Actions bump and fails there.** Severity: medium.
- **The sentence:** a matching upstream release opens a PR with ref, checksum and derived tags updated.
- **The code:** the `postUpgradeTasks` rule is keyed on `matchDatasources: ["github-tags"]` (renovate.json5:416-421). The built-in `github-actions` manager, enabled at renovate.json5:12, resolves actions through github-tags (Renovate dist manager/github-actions/extract.js:71). The command allowlist accepts it (renovate.yml:57). So an Actions bump runs `scripts/refresh-definition.sh .github/workflows`, which exits 1 with "refresh: no image.yaml in .github/workflows" (refresh-definition.sh:36; reproduced on a copy under /tmp/r3probe).
- **What happens next (from Renovate's code):**
  - A release younger than 2 h makes Renovate throw a branch error and open no PR (Renovate dist update/branch/index.js:458-471).
  - An older one gets a PR with a failed artifacts status.
  - The repository's own record of the same failure shape (kyverno, renovate.json5:428-431) says "the failed-artifact status write aborted the whole run". If that still holds, every Actions bump can end a Renovate run before the definition bumps queued after it.
- **Affected:** Actions bumps (Req 7.6), Actions security fixes, and possibly definition bumps in the same run. The files cannot show which outcome occurs live.
- **A related doc gap:** the precedent fix for the same collision (grafana, keyed by name, renovate.json5:426-433) was never applied to the github-tags rule. The rule's own comment (renovate.json5:413-414) says it was scoped "so docker digest bumps don't trigger it", which predates the Actions manager.

**r3.2 (Req 3.7): the minimum release age exempts more than the catalogue's own digests and the build layer.** Severity: medium.
- **The sentence:** every PR bumping a pinned third-party release version waits at least three days, exempting only the docker datasource of catalogue-published digests and hand-reviewed build-layer pins.
- **The code:** the age rule lists six datasources (renovate.json5:391-393). Three cases fall outside it:
  - **(a)** `PROBE_IMAGE` (`ghcr.io/curl/curl-container/curl-multi:8.11.1@sha256:…`, e2e.yml:124) is a third-party release tracked through the docker datasource (renovate.json5:198-210), so its bumps are offered the same day. docs/lanes.md:73 states this exemption openly; the requirement does not allow it.
  - **(b)** Every vulnerability-alert PR carries Renovate's default `minimumReleaseAge: null` (Renovate dist config/options/index.js:2050), applied with `force` (init/vulnerability.js:163-165). renovate.json5:46-48 does not override it. A security fix to a third-party version therefore opens unaged. This is a real conflict between 3.7 and 3.14 ("whatever that dependency's update scope"), and the code settles it without a recorded decision.
  - **(c)** The gomod manager extracts the `go` directives (test/go.mod:3, triage/rescan/go.mod:3) as the golang-version datasource (Renovate dist manager/gomod/line-parser.js:26-40), which is not in the list. Under go-mod-directive versioning such an update is rarely offered.
- **Affected:** the claim that every third-party bump is aged (the owner's view). A consumer is not directly affected.

**r3.3 (Req 3.14): alerts on GitHub Actions open no fix PR, and the alert read can fail silently.** Severity: medium.
- **(a) No Actions mapping.** Renovate maps alert ecosystems composer, go, maven, npm, nuget, pip, rubygems and rust only (Renovate dist init/vulnerability.js:70-79). An alert on an action (ecosystem `actions`) gets `matchDatasources: [undefined]` and matches nothing, so no fix PR opens. Even if it were mapped, r3.1 would fail its refresh task.
  - CONVENTIONS.md:497 (M25) names "the CI pins" among the dependencies whose alerts open a fix PR by default.
- **(b) The alert read depends on live state.** It needs RENOVATE_TOKEN's "Dependabot alerts: read" scope (renovate.yml:13-16) and Dependabot alerts enabled on the repository. Neither is asserted by any daily check:
  - check-governance.sh reads rulesets and private reporting only.
  - When the read fails, Renovate warns on the Dashboard and the run stays green (renovate.yml:15-16).
  - The manual's token row omits the scope (r3.7). A token rotated by the manual therefore loses 3.14 with nothing red.
- **Affected:** the repository's own tooling security fixes, which the owner believes are automatic.
